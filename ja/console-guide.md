## ロードバランサー(DSR)の管理

<a id='create-dsr-loadbalancers'></a>
### ロードバランサー(DSR)の作成
NHN Cloudコンソールでロードバランサー(DSR)の設定値を入力するだけで、簡単にDSR方式のロードバランサーを作成できます。ロードバランサー(DSR)はDSR(direct server return)方式で動作し、サーバーのレスポンストラフィックがロードバランサーを経由せずにクライアントへ直接送信されるため、高い処理性能を提供します。

ロードバランサー(DSR)の作成画面は、次の3つの領域で構成されています。

#### 1. ロードバランサー(DSR)の基本情報設定

ロードバランサー(DSR)の基本情報を設定します。必要な項目は以下の通りです。

* 名前: ロードバランサー(DSR)の名前を入力します。
* 説明: ロードバランサー(DSR)についての説明を記述します。
* VPC: ロードバランサー(DSR)が接続するVPCを選択します。
* サブネット: ロードバランサー(DSR)が属するサブネットを選択します。ロードバランサー(DSR)とメンバーインスタンスは同じサブネットに位置する必要があります。
* VIP(Virtual IP): ロードバランサー(DSR)に割り当てるVIPアドレスです。割り当て方式を**自動割り当て**または**直接指定**から選択できます。
  * 自動割り当て: サブネットの利用可能なIP の1つを自動的に割り当ててVIPとして使用します。
  * 直接指定: サブネットのCIDR範囲内で、希望するIPを直接入力してVIPとして使用します。

!!! danger "注意"
    直接指定したVIPアドレスがサブネットのCIDR範囲に属さない場合、作成は失敗します。必ずそのサブネットのIP範囲内で指定してください。

!!! tip "ポイント"
    ロードバランサー(DSR)はTCP/UDP L4レベルで動作し、サーバーのレスポンストラフィックはロードバランサーを経由しません。したがって、一般的なロードバランサーと異なり、L7機能(HTTPヘッダベースのルーティング、SSLオフロード、リスナー/メンバーグループの概念など)は提供されません。

#### 2. ヘルスチェック設定

メンバーインスタンスが正常に動作しているか定期的に確認するヘルスチェックを設定します。

* ヘルスチェックプロトコル: ヘルスチェックに使用するプロトコルを選択します。**TCP / ICMP / HTTP**のいずれかを選択します。
* 遅延時間: ヘルスチェックリクエストを送信する間隔(秒)です。
* 最大応答待機時間(タイムアウト): 各ヘルスチェックリクエストのタイムアウト時間(秒)です。この時間内に応答がない場合は失敗と判定されます。
* 最大リトライ回数: インスタンスを異常と判定するまでのリトライの最大回数です。(1～10回)

プロトコルごとに、以下のような追加項目を設定します。

**TCP**

* ヘルスチェックポート: TCP接続を試行するポート番号を指定します。

**ICMP**

* 別途のポート設定は不要です。ICMP Echo Request/Replyで接続性を確認します。

**HTTP**

* ヘルスチェックポート: HTTPリクエストを送信するポート番号を指定します。
* HTTPパス(URL): ヘルスチェックを実行するURLパスを入力します。デフォルト値は`/`です。
* 期待するHTTPレスポンスコード: 正常なレスポンスと判定するHTTPレスポンスコードを入力します。デフォルト値は`200`です。

!!! danger "注意"
    遅延時間はタイムアウト以上である必要があります。タイムアウトが遅延時間より大きい場合、ヘルスチェックが正常に動作しない可能性があります。

!!! tip "ポイント"
    TCP/HTTPヘルスチェックはDSR VIPを宛先としてリクエストするため、メンバーサーバーのloインターフェースにVIPが設定されていない場合、当該パケットが受信・処理されず、ヘルスチェックが失敗してメンバーが`INACTIVE`と判定されます。ICMPヘルスチェックはメンバーの実際のIPにリクエストするため、VIP設定とは無関係に接続性のみを確認します。

#### 3. メンバー設定

ロードバランサー(DSR)作成時に登録するメンバーインスタンスを指定します。メンバー登録はロードバランサー(DSR)作成後にも実行できます。

* インスタンス選択: ロードバランサー(DSR)と同じサブネットに属するインスタンス(ネットワークインターフェース)を選択します。複数のインスタンスを同時に選択してメンバーとして登録できます。

!!! tip "ポイント"
    ロードバランサー(DSR)はクライアントリクエストの宛先ポート(VIPポート)をそのままの状態でメンバーインスタンスに転送します。したがって、一般的なロードバランサーと異なり、メンバー登録時にメンバーごとのサービスポートを指定せず、メンバーインスタンスのネットワークインターフェースのみを選択します。メンバーサーバーのアプリケーションは`0.0.0.0`またはVIPにバインドされて、クライアントが送信した同一のポートをリッスン待機する必要があります。

!!! danger "注意"
    メンバーインスタンスがVIPへのトラフィックを正常に受信・応答するには、サーバー内部で以下の設定が必要です。

    - ネットワークインターフェースにVIPを追加許可アドレスとして追加(コンソールNetwork Interfaceメニュー)
    - カーネルパラメータ設定(`arp_ignore=1`, `arp_announce=2`)
    - loインターフェースにVIPを`/32`サブネットで追加
    - Security Groupsでサービスポートおよびヘルスチェックトラフィックを許可

    詳細な手順は[ロードバランサー(DSR)概要](/Network/Load%20Balancer(DSR)/ja/overview/)のメンバーサーバー設定ガイドを参照してください。

!!! tip "ポイント"
    新たに登録されたメンバーの初期状態は`INACTIVE`です。ヘルスチェックに合格すると自動的に`ACTIVE`状態に切り替わり、トラフィックを受信します。

すべての項目を入力した後、**ロードバランサー作成**ボタンをクリックするとロードバランサー(DSR)が作成されます。

<a id='view-dsr-loadbalancers'></a>
### ロードバランサー(DSR)の確認と修正

#### ロードバランサー(DSR)リスト

ロードバランサー(DSR)の作成が完了すると、リスト画面で作成されたロードバランサー(DSR)の基本情報を確認できます。リスト画面に表示される項目は以下の通りです。

* 名前: ロードバランサー(DSR)作成時に指定した名前です。
* VIPアドレス: ロードバランサー(DSR)に割り当てられたプライベートIPです。VPC内部からはこのIPでアクセスできます。
* フローティングIP: 外部からアクセスするために接続されたフローティングIPです。
* ネットワーク: ロードバランサー(DSR)が属するVPCの名前とサブネットCIDRです。
* メンバー数: ロードバランサー(DSR)に登録されたメンバーインスタンスの個数です。
* 状態: ロードバランサー(DSR)の作成/動作状態です。

!!! tip "ポイント"
    ロードバランサー(DSR)の状態は以下のいずれかで決まります。

    | 状態 | 意味 |
    |--|--|
    | `ACTIVE` | 正常に動作中 |
    | `BUILD` | ロードバランサー(DSR)作成中 |
    | `ERROR` | エラーが発生しました。管理者にお問い合わせください。 |

上部の**+ DSR作成**ボタンでロードバランサー(DSR)を追加作成でき、リストでチェックボックスでロードバランサー(DSR)を選択後、**削除**ボタンで削除できます。

#### ロードバランサー(DSR)の詳細情報

リストからロードバランサー(DSR)を選択すると、画面下部に詳細情報が表示されます。詳細画面は**基本情報**、**メンバー**、**ヘルスチェック**の3つのタブに分かれています。

**基本情報**タブでは、以下の情報を確認できます。

* 名前、説明
* サブネットおよびVIPアドレス
* フローティングIP接続情報
* 状態

#### 名前の変更
ロードバランサー(DSR)の名前を変更するには、詳細情報の**名前編集**アイコンをクリックして、変更する名前を入力した後、**確認**ボタンをクリックします。

#### フローティングIPの変更
外部ネットワークからロードバランサー(DSR)にアクセスできるようにフローティングIPを接続または解除できます。

1. ロードバランサー(DSR)詳細情報の**フローティングIP変更**ボタンをクリックします。
2. 接続するフローティングIPを選択します。フローティングIPを解除するには、**使用しない**を選択します。
3. **確認**ボタンをクリックすると、設定が適用されます。

!!! tip "ポイント"
    フローティングIPを解除しても、VPC内部からVIPを通じたアクセスは影響を受けません。

!!! tip "ポイント"
    ロードバランサー(DSR)が接続されているVPC、サブネット、VIPアドレスは作成後に変更できません。変更が必要な場合は、ロードバランサー(DSR)を削除してから再作成する必要があります。

<a id='delete-dsr-loadbalancers'></a>
### ロードバランサー(DSR)の削除
ロードバランサー(DSR)リスト画面で削除するロードバランサー(DSR)を選択した後、**削除**ボタンをクリックし、確認画面で**確認**ボタンをクリックすると、そのロードバランサー(DSR)が削除されます。

!!! danger "注意"
    ロードバランサー(DSR)を削除すると、そのDSRに登録されているすべてのメンバーも一緒に削除されます。フローティングIPが接続されている場合は、自動的に解除されます。

<a id='manage-dsr-members'></a>
## メンバーの管理

ロードバランサー(DSR)リストから目的のロードバランサー(DSR)を選択した後、**メンバー**タブをクリックするとメンバーインスタンス管理画面が表示されます。

### メンバーリスト

**メンバー**タブでは、ロードバランサー(DSR)に登録されたメンバーインスタンスのリストと状態を確認できます。リストに表示される項目は以下の通りです。

* IPアドレス: メンバーインスタンスのIPアドレスです。
* デバイスモデル: メンバーとして登録されたネットワークポートの所有リソースタイプです。
* デバイス情報: メンバーとして登録されたネットワークポートの識別情報(インスタンス名、ポートIDなど)が統合して表示されます。
* 状態: メンバーの現在の状態です。

!!! tip "ポイント"
    ロードバランサー(DSR)はクライアントリクエストの宛先ポートをそのままの状態でメンバーに転送するため、メンバー項目にはL4サービスポートが別途表示されません。実際のサービスポートはクライアントがVIPにリクエストしたポートであり、メンバーサーバーのアプリケーションがそのポートをリッスン待機する必要があります。

!!! tip "ポイント"
    メンバーの状態は以下のいずれかで決まります。

    | 状態 | 意味 |
    |--|--|
    | `ACTIVE` | ヘルスチェック成功、トラフィック分散の対象 |
    | `INACTIVE` | ヘルスチェック失敗または新規登録直後、トラフィック分散の対象外 |
    | `ONLINE` | メンバーが手動で無効化された状態 |

<a id='add-dsr-members'></a>
### メンバーの追加
**メンバー**タブで**+ メンバー追加**ボタンをクリックするとメンバー追加モーダルが表示されます。

1. リストからメンバーとして登録する**インスタンス**を選択します。複数のインスタンスを同時に選択できます。
2. **確認**ボタンをクリックすると、選択したインスタンスがメンバーとして登録されます。

!!! tip "ポイント"
    一般的なロードバランサーとは異なり、ロードバランサー(DSR)はメンバー追加段階でL4サービスポートを入力しません。ロードバランサー(DSR)がクライアントリクエストの宛先ポートを変換なしでそのままメンバーに転送するため、メンバーごとのポートマッピングは不要です。

!!! danger "注意"
    メンバー登録時に以下の制限事項に注意してください。

    * メンバーインスタンスはロードバランサー(DSR)と同じサブネットに属する必要があります。
    * コンピュートインスタンスのみをメンバーとして登録できます。
    * 同じインスタンスポートを同じロードバランサー(DSR)に重複して登録することはできません。
    * 1つのロードバランサー(DSR)には基本的に最大30個のメンバーを登録できます。

!!! tip "ポイント"
    メンバー登録後、トラフィックを正常に受信するには、ネットワークインターフェースにVIPを追加許可アドレスとして追加し、メンバーサーバー内部でARP カーネルパラメータ設定、loインターフェースへのVIP追加、Security Groups規則設定が必要です。詳細な手順は[ロードバランサー(DSR)概要](/Network/Load%20Balancer(DSR)/ja/overview/)のメンバーサーバー設定ガイドを参照してください。

<a id='delete-dsr-members'></a>
### メンバーの削除
メンバータブのリストから削除するメンバーを選択した後、**削除**ボタンをクリックします。確認画面が表示されたら**確認**ボタンをクリックすると、そのメンバーがロードバランサー(DSR)から削除されます。

!!! tip "ポイント"
    ロードバランサー(DSR)からメンバーを削除しても、当該インスタンス自体は削除されません。逆に、メンバーとして登録されたインスタンスを削除すると、そのメンバーは自動的にロードバランサー(DSR)から削除されます。

## ヘルスチェックの管理

ロードバランサー(DSR)詳細画面の**ヘルスチェック**タブで、現在設定されているヘルスチェック情報を確認および変更できます。

<a id='view-dsr-health-monitor'></a>
### ヘルスチェックの確認
**ヘルスチェック**タブでは、現在設定されているヘルスチェックの以下の情報を確認できます。

* ヘルスチェックプロトコル: TCP / ICMP / HTTP
* ヘルスチェックポート: TCPまたはHTTPプロトコル使用時のヘルスチェック対象ポート
* 遅延時間: ヘルスチェックリクエスト間隔(秒)
* 最大応答待機時間: ヘルスチェックタイムアウト(秒)
* 最大リトライ回数: 異常判定までのリトライ回数
* HTTPパス(URL) / 期待するHTTPレスポンスコード: HTTPプロトコル使用時にのみ表示

<a id='change-dsr-health-monitor'></a>
### ヘルスチェック設定の変更
**ヘルスチェック**タブで**設定変更**ボタンをクリックするとヘルスチェック設定を変更できます。

* ヘルスチェックプロトコル: TCP / ICMP / HTTPから選択
* プロトコルごとの必須項目を入力します。
  * TCP: ヘルスチェックポート
  * ICMP: 追加項目なし
  * HTTP: ヘルスチェックポート、HTTPパス、期待するHTTPレスポンスコード
* 遅延時間、最大応答待機時間、最大リトライ回数を設定します。

設定完了後、**確認**ボタンをクリックすると変更が適用されます。

!!! danger "注意"
    遅延時間はタイムアウト以上である必要があります。タイムアウトが遅延時間より大きい場合、ヘルスチェックが正常に動作しない可能性があります。

!!! tip "ポイント"
    ヘルスチェックリクエストはロードバランサー(DSR)と同じサブネットに自動割り当てされたヘルスチェック専用IPから送信されます。メンバーインスタンスのSecurity Groupでそのトラフィックを許可する必要があります。詳細は[ロードバランサー(DSR)概要](/Network/Load%20Balancer(DSR)/ja/overview/)のSecurity Groups設定セクションを参照してください。

<a id='dsr-quota'></a>
## クォータと制限事項

ロードバランサー(DSR)の使用時に、以下のクォータおよび制限が適用されます。

| 項目 | デフォルト制限 | 説明 |
|--|--|--|
| プロジェクトごとのロードバランサー(DSR)数 | 10個 | プロジェクトごとに作成できるロードバランサー(DSR)の個数 |
| ロードバランサー(DSR)ごとのメンバー数 | 30個 | 1つのロードバランサー(DSR)に登録可能なメンバーの個数 |

!!! tip "ポイント"
    デフォルトクォータを超えて使用する必要がある場合は、カスタマーサポートにお問い合わせください。
