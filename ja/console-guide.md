## ロードバランサー(DSR)管理 { #manage-dsr-loadbalancers }

<a id='create-dsr-loadbalancers'></a>
### ロードバランサー(DSR)の作成 { #create-dsr-loadbalancers }
NHN Cloudコンソールでロードバランサー(DSR)の設定値を入力するだけで、簡単にDSR方式のロードバランサーを作成できます。ロードバランサー(DSR)はDSR(direct server return)方式で動作し、サーバーのレスポンストラフィックがロードバランサーを経由せずにクライアントへ直接転送されるため、高い処理性能を提供します。

ロードバランサー(DSR)作成画面は、次の3つの領域で構成されます。

<a id='create-dsr-loadbalancers-load-balancer-dsr-basic-information-settings'></a>
#### 1. ロードバランサー(DSR)の基本情報設定

ロードバランサー(DSR)に関する基本情報を設定します。必要な項目は次のとおりです。

* 名前: ロードバランサー(DSR)の名前を入力します。
* 説明: ロードバランサー(DSR)の説明を入力します。
* VPC: ロードバランサー(DSR)が接続されるVPCを選択します。
* サブネット: ロードバランサー(DSR)が属するサブネットを選択します。ロードバランサー(DSR)とメンバーインスタンスは同じサブネットに配置する必要があります。
* VIP（Virtual IP）: ロードバランサー(DSR)が使用するVIPアドレスで、選択したサブネットから割り当てられるプライベートIPです。割り当て方式を **[自動割り当て]** または **[直接指定]** から選択できます。
  * 自動割り当て: サブネットの使用可能なIPの中から1つを自動的に割り当て、VIPとして使用します。
  * 直接指定: サブネットのCIDR範囲内で任意のIPを直接入力し、VIPとして使用します。

!!! danger "注意"
    直接指定したVIPアドレスがサブネットのCIDR範囲に含まれていない場合、作成に失敗します。必ず該当サブネットのIP範囲内で指定してください。

!!! tip "ポイント"
    ロードバランサー(DSR)はTCP/UDP L4レベルで動作し、サーバーのレスポンストラフィックはロードバランサーを経由しません。そのため、一般的なロードバランサーとは異なり、L7機能(HTTPヘッダーベースのルーティング、SSL Offloading、リスナー/メンバーグループの概念など)は提供されません。

<a id='create-dsr-loadbalancers-health-check-settings'></a>
#### 2. ヘルスチェック設定

メンバーインスタンスが正常に動作しているかを定期的に確認するヘルスチェックを設定します。

* ヘルスチェックプロトコル: ヘルスチェックに使用するプロトコルを選択します。**TCP / ICMP / HTTP**から1つを選択します。
* 遅延時間: ヘルスチェックリクエストを送信する周期(秒)です。
* 最大応答待機時間(タイムアウト): 各ヘルスチェックリクエストのタイムアウト時間(秒)です。この時間内に応答がない場合は失敗とみなされます。
* 最大再試行回数: インスタンスを異常と判断するまでに再試行する最大回数です。(1～10回)

プロトコル別に、次のように追加項目を設定します。

**TCP**

* ヘルスチェックポート: TCP接続を試行するポート番号を指定します。

**ICMP**

* 別途のポート設定は不要です。ICMP Echo Request/Replyで接続性を確認します。

**HTTP**

* ヘルスチェックポート: HTTPリクエストを送信するポート番号を指定します。
* HTTPパス(URL): ヘルスチェックを実行するURLパスを入力します。デフォルト値は`/`です。
* 期待するHTTPステータスコード: 正常なレスポンスとみなすHTTPステータスコードを入力します。デフォルト値は`200`です。

!!! danger "注意"
    遅延時間はタイムアウト以上である必要があります。タイムアウトが遅延時間より大きい場合、ヘルスチェックが正常に動作しない可能性があります。

!!! tip "ポイント"
    TCP/HTTP ヘルスチェックは DSR VIP（プライベートIP）を宛先としてリクエストするため、メンバーサーバーのloインターフェースにVIPが設定されていない場合、該当するパケットが受信・処理されず、ヘルスチェックが失敗してメンバーが `INACTIVE` と判定されます。ICMP ヘルスチェックはメンバーの実際のIPにリクエストするため、VIPの設定に関わらず接続性のみを確認します。

<a id='create-dsr-loadbalancers-member-settings'></a>
#### 3. メンバー設定

ロードバランサー(DSR)作成時に登録するメンバーインスタンスを指定します。メンバー登録は、ロードバランサー(DSR)作成後にも行うことができます。

* インスタンスの選択: ロードバランサー(DSR)と同じサブネットに属するインスタンス(ネットワークインターフェース)を選択します。複数のインスタンスを同時に選択してメンバーとして登録できます。

!!! tip "ポイント"
    ロードバランサー(DSR)は、クライアントリクエストの宛先ポート(VIPポート)をそのまま維持してメンバーインスタンスへ転送します。したがって、一般的なロードバランサーとは異なり、メンバー登録時にメンバー別のサービスポートを指定せず、メンバーインスタンスのネットワークインターフェースのみを選択します。メンバーサーバーのアプリケーションは`0.0.0.0`またはVIPにバインドされ、クライアントが送信した同一のポートをListenする必要があります。

!!! danger "注意"
    メンバーインスタンスがVIP宛てのトラフィックを正常に受信・応答するには、サーバー内部で次の設定が必要です。

    - ネットワークインターフェースにVIPを追加許可アドレスとして追加（コンソールのNetwork Interfaceメニュー）
    - カーネルパラメータの設定（`arp_ignore=1`、`arp_announce=2`）
    - loインターフェースにVIPを`/32`サブネットとして追加
    - Security Groupsでサービスポートおよびヘルスチェックトラフィックを許可

    loインターフェースおよび追加許可アドレスに登録するアドレスはVIP（プライベートIP）であり、ロードバランサー（DSR）に関連付けたフローティングIPではありません。

    詳細な手順については、[ロードバランサー（DSR）概要](/Network/Load%20Balancer(DSR)/ja/overview/)のメンバーサーバー設定ガイドを参照してください。

!!! tip "ポイント"
    新しく登録されたメンバーの初期状態は`INACTIVE`です。ヘルスチェックを通過すると自動的に`ACTIVE`状態に切り替わり、トラフィックを受信します。

全ての項目を入力後、**ロードバランサーの作成**ボタンをクリックすると、ロードバランサー(DSR)が作成されます。

<a id='view-dsr-loadbalancers'></a>
### ロードバランサー(DSR)の確認及び修正 { #view-dsr-loadbalancers }

<a id='view-dsr-loadbalancers-load-balancer-dsr-list'></a>
#### ロードバランサー(DSR)の一覧

ロードバランサー(DSR)の作成が完了すると、一覧画面で作成されたロードバランサー(DSR)の基本情報を確認できます。一覧画面に表示される項目は次のとおりです。

* 名前: ロードバランサー(DSR)作成時に指定した名前です。
* VIPアドレス: ロードバランサー(DSR)に割り当てられたプライベートIPです。VPC内部からはこのIPでアクセスできます。
* フローティングIP: 外部からアクセスするために接続されたフローティングIPです。
* ネットワーク: ロードバランサー(DSR)が属するVPCの名前とサブネットCIDRです。
* メンバー数: ロードバランサー(DSR)に登録されているメンバーインスタンスの数です。
* 状態: ロードバランサー(DSR)の作成/動作状態です。

!!! tip "ポイント"
    ロードバランサー(DSR)の状態は以下のいずれかに決定されます。

    | 状態 | 意味 |
    |--|--|
    | `ACTIVE` | 正常動作中 |
    | `BUILD` | ロードバランサー(DSR)の作成中 |
    | `ERROR` | エラー発生。管理者にお問い合わせください。 |

上部の**+ DSR作成**ボタンからロードバランサー(DSR)を追加作成でき、一覧のチェックボックスでロードバランサー(DSR)を選択した後、**削除**ボタンで削除できます。

<a id='view-dsr-loadbalancers-load-balancer-dsr-details'></a>
#### ロードバランサー(DSR)の詳細情報

一覧からロードバランサー(DSR)を選択すると、画面下部に詳細情報が表示されます。詳細画面は**基本情報**、**メンバー**、**ヘルスチェック**の3つのタブに分かれています。

**基本情報**タブでは、以下の情報を確認できます。

* 名前、説明
* サブネットおよびVIPアドレス
* フローティングIP接続情報
* 削除保護の設定有無
* 状態

<a id='view-dsr-loadbalancers-rename'></a>
#### 名前の変更
ロードバランサー(DSR)の名前を変更するには、詳細情報の**名前の変更**アイコンをクリックし、変更する名前を入力した後、**確認**ボタンをクリックします。

<a id='view-dsr-loadbalancers-change-floating-ip'></a>
#### フローティングIPの変更
外部ネットワークからロードバランサー(DSR)にアクセスできるように、フローティングIPを接続または解除できます。

1. ロードバランサー(DSR)の詳細情報にある**フローティングIP変更**ボタンをクリックします。
2. 接続するフローティングIPを選択します。フローティングIPを解除する場合は、**使用しない**を選択します。
3. **確認**ボタンをクリックすると、設定が適用されます。

!!! tip "ポイント"
    フローティングIPを解除しても、VPC内部でVIPを通じたアクセスは影響を受けません。

!!! tip "ポイント"
    ロードバランサー(DSR)が接続されたVPC、サブネット、VIPアドレスは作成後に変更できません。変更が必要な場合は、ロードバランサー(DSR)を削除してから再作成する必要があります。

<a id='view-dsr-loadbalancers-delete-protection'></a>
#### 削除保護
削除保護を有効にすると、誤ってロードバランサー(DSR)が削除されないよう保護できます。削除保護を無効にするまで、該当のロードバランサー(DSR)を削除することはできません。削除保護の設定は、ロードバランサー(DSR)を作成した後でもいつでも変更できます。

<a id='delete-dsr-loadbalancers'></a>
### ロードバランサー(DSR)の削除 { #delete-dsr-loadbalancers }
ロードバランサー(DSR)の一覧画面で削除するロードバランサー(DSR)を選択し、**削除**ボタンをクリックして確認ウィンドウで**確認**ボタンをクリックすると、該当のロードバランサー(DSR)が削除されます。

!!! danger "注意"
    ロードバランサー(DSR)を削除すると、該当のDSRに登録されている全てのメンバーも一緒に削除されます。フローティングIPが接続されていた場合は自動的に解除されます。

!!! tip "ヒント"
    削除保護が有効になっているロードバランサー(DSR)は削除することはできません。削除するには、まず該当するロードバランサー(DSR)の[削除保護](#view-dsr-loadbalancers-delete-protection)を無効にする必要があります。

<a id='manage-dsr-members'></a>
## メンバー管理 { #manage-dsr-members }

ロードバランサー(DSR)の一覧から任意のロードバランサー(DSR)を選択し、**メンバー**タブをクリックすると、メンバーインスタンスの管理画面が表示されます。

<a id='member-list'></a>
### メンバーの一覧 { #member-list }

**メンバー**タブでは、ロードバランサー(DSR)に登録されているメンバーインスタンスの一覧と状態を確認できます。一覧に表示される項目は次のとおりです。

* IPアドレス: メンバーインスタンスのIPアドレスです。
* デバイスモデル: メンバーとして登録されたネットワークポートの所有リソースタイプです。
* デバイス情報: メンバーとして登録されたネットワークポートの識別情報(インスタンス名、ポートIDなど)が統合して表示されます。
* 状態: メンバーの現在の状態です。

!!! tip "ポイント"
    ロードバランサー(DSR)は、クライアントリクエストの宛先ポートをそのまま維持してメンバーへ転送するため、メンバー項目にL4サービスポートは別途表示されません。実際のサービスポートはクライアントがVIP宛てにリクエストしたポートであり、メンバーサーバーのアプリケーションが該当のポートをListenする必要があります。

!!! tip "ポイント"
    メンバーの状態は以下のいずれかに決定されます。

    | 状態 | 意味 |
    |--|--|
    | `ACTIVE` | ヘルスチェック成功、トラフィック分散対象 |
    | `INACTIVE` | ヘルスチェック失敗または新規登録直後、トラフィック分散対象から除外 |
    | `ONLINE` | メンバーが手動で無効化された状態 |

<a id='add-dsr-members'></a>
### メンバーの追加 { #add-dsr-members }
**メンバー**タブで**+ メンバー追加**ボタンをクリックすると、メンバー追加モーダルが表示されます。

1. 一覧からメンバーとして登録する**インスタンス**を選択します。複数のインスタンスを同時に選択できます。
2. **確認**ボタンをクリックすると、選択したインスタンスがメンバーとして登録されます。

!!! tip "ポイント"
    一般的なロードバランサーとは異なり、ロードバランサー(DSR)はメンバー追加段階でL4サービスポートを入力しません。ロードバランサー(DSR)がクライアントリクエストの宛先ポートを変換せずにそのままメンバーへ転送するため、メンバーごとのポートマッピングは不要です。

!!! danger "注意"
    メンバー登録時は、以下の制限事項に留意してください。

    * メンバーインスタンスは、ロードバランサー(DSR)と同じサブネットに属している必要があります。
    * コンピュートインスタンスのみをメンバーとして登録できます。
    * 同一のインスタンスポートを同じロードバランサー(DSR)に重複して登録することはできません。
    * 1つのロードバランサー(DSR)には、デフォルトで最大30個のメンバーを登録できます。

!!! tip "ポイント"
    メンバー登録後、トラフィックを正常に受信するためには、ネットワークインターフェースにVIPを追加許可アドレスとして追加し、メンバーサーバー内部でARPカーネルパラメータの設定、loインターフェースへのVIP追加、Security Groupsルールの設定が必要です。詳細な手順については、[ロードバランサー(DSR)の概要](/Network/Load%20Balancer(DSR)/ja/overview/)のメンバーサーバー設定ガイドを参照してください。

<a id='deactivate-dsr-members'></a>
### メンバーの無効化 { #deactivate-dsr-members }
特定のメンバーを削除せずに、一時的にサービスから除外できます。**[メンバー]** タブのリストから除外するメンバーを選択し、**[メンバーの無効化]** をクリックした後、**[確認]** をクリックします。無効化されたメンバーの状態は `ONLINE` に変更され、トラフィック分散の対象から除外されます。

!!! tip "ご注意"
    無効化されたメンバーはロードバランサー(DSR)から削除されず、登録された状態のまま維持されるため、ロードバランサー(DSR)あたりのメンバー数クォータには引き続き含まれます。メンバーステータス値の詳細については、[メンバーリスト](#member-list)を参照してください。

<a id='delete-dsr-members'></a>
### メンバーの削除 { #delete-dsr-members }
メンバータブの一覧から削除するメンバーを選択し、**削除**ボタンをクリックします。確認ウィンドウが表示されたら**確認**ボタンをクリックすると、該当のメンバーがロードバランサー(DSR)から削除されます。

!!! tip "ポイント"
    ロードバランサー(DSR)からメンバーを削除しても、該当のインスタンス自体は削除されません。逆に、メンバーとして登録されているインスタンスを削除すると、そのメンバーは自動的にロードバランサー(DSR)から削除されます。

<a id='manage-dsr-health-monitor'></a>
## ヘルスチェック管理 { #manage-dsr-health-monitor }

ロードバランサー(DSR)の詳細画面の**ヘルスチェック**タブで、現在設定されているヘルスチェック情報を確認及び変更できます。

<a id='view-dsr-health-monitor'></a>
### ヘルスチェックの照会 { #view-dsr-health-monitor }
**ヘルスチェック**タブでは、現在設定されているヘルスチェックの以下の情報を確認できます。

* ヘルスチェックプロトコル: TCP / ICMP / HTTP
* ヘルスチェックポート: TCPまたはHTTPプロトコル使用時のヘルスチェック対象ポート
* 遅延時間: ヘルスチェックのリクエスト周期(秒)
* 最大応答待機時間: ヘルスチェックのタイムアウト(秒)
* 最大再試行回数: 異常判定までの再試行回数
* HTTPパス(URL) / 期待するHTTPステータスコード: HTTPプロトコル使用時にのみ表示

<a id='change-dsr-health-monitor'></a>
### ヘルスチェック設定の変更 { #change-dsr-health-monitor }
**ヘルスチェック**タブで**設定変更**ボタンをクリックすると、ヘルスチェック設定を変更できます。

* ヘルスチェックプロトコル: TCP / ICMP / HTTPから選択
* プロトコル別の必須項目を入力します。
  * TCP: ヘルスチェックポート
  * ICMP: 追加項目なし
  * HTTP: ヘルスチェックポート、HTTPパス、期待するHTTPステータスコード
* 遅延時間、最大応答待機時間、最大再試行回数を設定します。

設定完了後、**確認**ボタンをクリックすると変更事項が適用されます。

!!! danger "注意"
    遅延時間はタイムアウト以上である必要があります。タイムアウトが遅延時間より大きい場合、ヘルスチェックが正常に動作しない可能性があります。

!!! tip "ポイント"
    ヘルスチェックリクエストは、ロードバランサー(DSR)と同じサブネットに自動割り当てされたヘルスチェック専用IPから送信されます。メンバーインスタンスのSecurity Groupsで、該当するサブネットCIDRをリモートに指定してトラフィックを許可することで、ヘルスチェックが正常に動作します。詳細については、[ロードバランサー(DSR) 概要](/Network/Load%20Balancer(DSR)/ja/overview/)のSecurity Groups設定セクションを参照してください。

<a id='dsr-quota'></a>
## クォータ及び制限事項 { #dsr-quota }

ロードバランサー(DSR)を使用する際は、以下のクォータ及び制限が適用されます。

| 項目 | デフォルト制限 | 説明 |
|--|--|--|
| プロジェクトごとのロードバランサー(DSR)数 | 10個 | プロジェクトごとに作成可能なロードバランサー(DSR)の数 |
| ロードバランサー(DSR)ごとのメンバー数 | 30個 | 1つのロードバランサー(DSR)に登録可能なメンバーの数 |

!!! tip "ポイント"
    デフォルトのクォータを超過して使用する必要がある場合は、カスタマーサポートへお問い合わせください。
