## ロードバランサー(DSR)管理

<a id='create-dsr-loadbalancers'></a>
### ロードバランサー(DSR)作成
NHN Cloudコンソールでロードバランサー(DSR)の設定値を入力するだけで、DSR方式のロードバランサーを簡単に作成できます。ロードバランサー(DSR)は、DSR(direct server return)方式で動作し、サーバーのレスポンストラフィックがロードバランサーを経由せずにクライアントへ直接送信されるため、高い処理性能を提供します。

ロードバランサー(DSR)作成画面は、次の3つのエリアで構成されています。

#### 1. ロードバランサー(DSR)基本情報設定

ロードバランサー(DSR)の基本情報を設定します。必要な項目は次のとおりです。

* 名前: ロードバランサー(DSR)の名前を入力します。
* 説明: ロードバランサー(DSR)の説明を記述します。
* VPC: ロードバランサー(DSR)が接続されるVPCを選択します。
* サブネット: ロードバランサー(DSR)が属するサブネットを選択します。ロードバランサー(DSR)とメンバーインスタンスは同一のサブネットに位置する必要があります。
* VIP(Virtual IP): ロードバランサー(DSR)に割り当てるVIPアドレスです。割り当て方式を**自動割り当て**または**直接指定**から選択できます。
  * 自動割り当て: サブネットの使用可能IPの中から自動的に割り当てを受けてVIPとして使用します。
  * 直接指定: サブネットのCIDR範囲内で希望するIPを直接入力してVIPとして使用します。

!!! danger "注意"
    直接指定したVIPアドレスがサブネットのCIDR範囲に属していないと作成に失敗します。必ずそのサブネットのIP範囲内で指定してください。

!!! tip "ポイント"
    ロードバランサー(DSR)は、TCP/UDP L4レベルで動作し、サーバーのレスポンストラフィックがロードバランサーを経由しません。そのため、一般的なロードバランサーとは異なり、L7機能(HTTPヘッダベースのルーティング、SSL Offloading、リスナー/メンバーグループの概念など)は提供されません。

#### 2. ヘルスチェック設定

メンバーインスタンスが正常に動作しているか定期的に確認するヘルスチェックを設定します。

* ヘルスチェックプロトコル: ヘルスチェックに使用するプロトコルを選択します。**TCP / ICMP / HTTP**のいずれかを選択します。
* 遅延時間: ヘルスチェック要求を送信する周期(秒)です。
* 最大応答待機時間(タイムアウト): 各ヘルスチェック要求のタイムアウト時間(秒)です。この時間内に応答がないと失敗とみなします。
* 最大リトライ回数: インスタンスを異常と判定するまでのリトライ最大回数です。(1~10回)

プロトコル別に次のように追加項目を設定します。

**TCP**

* ヘルスチェックポート: TCP接続を試行するポート番号を指定します。

**ICMP**

* 別途のポート設定は必要ありません。ICMP Echo Request/Replyで接続性を確認します。

**HTTP**

* ヘルスチェックポート: HTTP要求を送信するポート番号を指定します。
* HTTPパス(URL): ヘルスチェックを実行するURLパスを入力します。デフォルト値は`/`です。
* 期待するHTTPレスポンスコード: 正常レスポンスとみなすHTTPレスポンスコードを入力します。デフォルト値は`200`です。

!!! danger "注意"
    遅延時間は、タイムアウトより大きいかそれと等しくなければなりません。タイムアウトが遅延時間より大きいと、ヘルスチェックが正常に動作しない場合があります。

!!! tip "ポイント"
    TCP/HTTPヘルスチェックは、DSR VIPを宛先として要求するため、メンバーサーバーのloインターフェースにVIPが設定されていないと、該当パケットが受信・処理されずヘルスチェックが失敗し、メンバーが`INACTIVE`と判定されます。ICMPヘルスチェックは、メンバーの実際のIPに要求するため、VIP設定に関係なく接続性のみ確認します。

#### 3. メンバー設定

ロードバランサー(DSR)作成時に登録するメンバーインスタンスを指定します。メンバー登録は、ロードバランサー(DSR)作成後にも行えます。

* インスタンス選択: ロードバランサー(DSR)と同一のサブネットに属するインスタンス(ネットワークインターフェース)を選択します。1つ以上のインスタンスを同時に選択してメンバーとして登録できます。

!!! tip "ポイント"
    ロードバランサー(DSR)は、クライアント要求の宛先ポート(VIPポート)をそのまま保持したままメンバーインスタンスに転送します。そのため、一般的なロードバランサーとは異なり、メンバー登録時にメンバー別のサービスポートを指定せず、メンバーインスタンスのネットワークインターフェースのみ選択します。メンバーサーバーのアプリケーションは、`0.0.0.0`またはVIPにバインドして、クライアントが送信した同じポートを受信待機する必要があります。

!!! danger "注意"
    メンバーインスタンスがVIPからのトラフィックを正常に受信・応答するためには、サーバー内部で次の設定が必要です。

    - ネットワークインターフェースにVIPを追加許可アドレスとして追加(コンソールNetwork Interfaceメニュー)
    - カーネルパラメータ設定(`arp_ignore=1`、`arp_announce=2`)
    - loインターフェースにVIPを`/32`サブネットで追加
    - Security Groupsでサービスポートおよびヘルスチェックトラフィックの許可

    詳細な手順は、[ロードバランサー(DSR)概要](/Network/Load%20Balancer(DSR)/ja/overview/)のメンバーサーバー設定ガイドを参照してください。

!!! tip "ポイント"
    新しく登録されたメンバーの初期状態は`INACTIVE`です。ヘルスチェックに合格すると、自動的に`ACTIVE`状態に切り替わってトラフィックを受信します。

すべての項目入力後、**ロードバランサー作成**ボタンをクリックすると、ロードバランサー(DSR)が作成されます。

<a id='view-dsr-loadbalancers'></a>
### ロードバランサー(DSR)の確認と修正

#### ロードバランサー(DSR)一覧

ロードバランサー(DSR)の作成が完了すると、一覧画面で作成されたロードバランサー(DSR)の基本情報を確認できます。一覧画面で表示される項目は次のとおりです。

* 名前: ロードバランサー(DSR)作成時に指定した名前です。
* VIPアドレス: ロードバランサー(DSR)に割り当てられた私設IPです。VPC内部では、このIPでアクセスできます。
* FloatingIP: 外部からアクセスするために接続されたFloatingIPです。
* ネットワーク: ロードバランサー(DSR)が属するVPCの名前とサブネットCIDRです。
* メンバー数: ロードバランサー(DSR)に登録されたメンバーインスタンスの個数です。
* 状態: ロードバランサー(DSR)の作成/動作状態です。

!!! tip "ポイント"
    ロードバランサー(DSR)の状態は次のいずれかで決定されます。

    | 状態 | 意味 |
    |--|--|
    | `ACTIVE` | 正常動作中 |
    | `BUILD` | ロードバランサー(DSR)作成中 |
    | `ERROR` | エラー発生。管理者にお問い合わせください。 |

上部の**+ DSR作成**ボタンでロードバランサー(DSR)を追加作成でき、一覧でチェックボックスでロードバランサー(DSR)を選択した後、**削除**ボタンで削除できます。

#### ロードバランサー(DSR)詳細情報

一覧でロードバランサー(DSR)を選択すると、画面下部に詳細情報が表示されます。詳細画面は、**基本情報**、**メンバー**、**ヘルスチェック**の3つのタブに区分されます。

**基本情報**タブでは、次の情報を確認できます。

* 名前、説明
* サブネットおよびVIPアドレス
* FloatingIP接続情報
* 状態

#### 名前変更
ロードバランサー(DSR)の名前を変更するには、詳細情報の**名前修正**アイコンをクリックして変更する名前を入力した後、**確認**ボタンをクリックします。

#### FloatingIP変更
外部ネットワークからロードバランサー(DSR)にアクセスできるよう、FloatingIPを接続したり分離したりできます。

1. ロードバランサー(DSR)詳細情報の**FloatingIP変更**ボタンをクリックします。
2. 接続するFloatingIPを選択します。FloatingIPを分離する場合は、**使用しない**を選択します。
3. **確認**ボタンをクリックすると設定が適用されます。

!!! tip "ポイント"
    FloatingIPを分離してもVPC内部でのVIPを通じたアクセスは影響を受けません。

!!! tip "ポイント"
    ロードバランサー(DSR)が接続されたVPC、サブネット、VIPアドレスは作成後に変更できません。変更が必要な場合は、ロードバランサー(DSR)を削除してから再作成する必要があります。

<a id='delete-dsr-loadbalancers'></a>
### ロードバランサー(DSR)削除
ロードバランサー(DSR)一覧画面で削除するロードバランサー(DSR)を選択した後、**削除**ボタンをクリックし、確認ウィンドウで**確認**ボタンをクリックすると、該当ロードバランサー(DSR)が削除されます。

!!! danger "注意"
    ロードバランサー(DSR)を削除すると、該当DSRに登録されたすべてのメンバーが一緒に削除されます。FloatingIPが接続されている場合は自動的に解除されます。

<a id='manage-dsr-members'></a>
## メンバー管理

ロードバランサー(DSR)一覧で希望するロードバランサー(DSR)を選択した後、**メンバー**タブをクリックすると、メンバーインスタンス管理画面が表示されます。

### メンバー一覧

**メンバー**タブでは、ロードバランサー(DSR)に登録されたメンバーインスタンスの一覧と状態を確認できます。一覧に表示される項目は次のとおりです。

* IPアドレス: メンバーインスタンスのIPアドレスです。
* デバイスモデル: メンバーとして登録されたネットワークポートの所有リソースタイプです。
* デバイス情報: メンバーとして登録されたネットワークポートの識別情報(インスタンス名、ポートIDなど)が統合されて表示されます。
* 状態: メンバーの現在の状態です。

!!! tip "ポイント"
    ロードバランサー(DSR)は、クライアント要求の宛先ポートをそのまま保持したままメンバーに転送するため、メンバー項目にはL4サービスポートが別途表示されません。実際のサービスポートは、クライアントがVIPに要求したポートであり、メンバーサーバーのアプリケーションが該当ポートを受信待機(Listen)する必要があります。

!!! tip "ポイント"
    メンバーの状態は次のいずれかで決定されます。

    | 状態 | 意味 |
    |--|--|
    | `ACTIVE` | ヘルスチェック成功、トラフィック分散対象 |
    | `INACTIVE` | ヘルスチェック失敗または新規登録直後、トラフィック分散対象から除外 |
    | `ONLINE` | メンバーが手動で非活性化された状態 |

<a id='add-dsr-members'></a>
### メンバー追加
**メンバー**タブで**+ メンバー追加**ボタンをクリックすると、メンバー追加モーダルが表示されます。

1. 一覧からメンバーとして登録する**インスタンス**を選択します。1つ以上のインスタンスを同時に選択できます。
2. **確認**ボタンをクリックすると、選択したインスタンスがメンバーとして登録されます。

!!! tip "ポイント"
    一般的なロードバランサーとは異なり、ロードバランサー(DSR)は、メンバー追加段階でL4サービスポートを入力しません。ロードバランサー(DSR)がクライアント要求の宛先ポートを変換せずにそのままメンバーに転送するため、メンバー別のポートマッピングが不要です。

!!! danger "注意"
    メンバー登録時に次の制約事項にご注意ください。

    * メンバーインスタンスは、ロードバランサー(DSR)と同一のサブネットに属する必要があります。
    * コンピュートインスタンスのみメンバーとして登録できます。
    * 同一のインスタンスポートを同じロードバランサー(DSR)に重複して登録できません。
    * 1つのロードバランサー(DSR)には、基本的に最大30個のメンバーを登録できます。

!!! tip "ポイント"
    メンバー登録後、トラフィックを正常に受信するためには、ネットワークインターフェースにVIPを追加許可アドレスとして追加し、メンバーサーバー内部でARPカーネルパラメータ設定、loインターフェースにVIP追加、Security Groupsルール設定が必要です。詳細な手順は、[ロードバランサー(DSR)概要](/Network/Load%20Balancer(DSR)/ja/overview/)のメンバーサーバー設定ガイドを参照してください。

<a id='delete-dsr-members'></a>
### メンバー削除
メンバータブの一覧で削除するメンバーを選択した後、**削除**ボタンをクリックします。確認ウィンドウが表示されたら**確認**ボタンをクリックすると、該当メンバーがロードバランサー(DSR)から削除されます。

!!! tip "ポイント"
    ロードバランサー(DSR)からメンバーを削除しても、該当インスタンス自体は削除されません。逆に、メンバーとして登録されたインスタンスを削除すると、該当メンバーは自動的にロードバランサー(DSR)から削除されます。

## ヘルスチェック管理

ロードバランサー(DSR)詳細画面の**ヘルスチェック**タブで、現在設定されたヘルスチェック情報を確認し、変更できます。

<a id='view-dsr-health-monitor'></a>
### ヘルスチェック照会
**ヘルスチェック**タブでは、現在設定されたヘルスチェックの次の情報を確認できます。

* ヘルスチェックプロトコル: TCP / ICMP / HTTP
* ヘルスチェックポート: TCPまたはHTTPプロトコル使用時のヘルスチェック対象ポート
* 遅延時間: ヘルスチェック要求周期(秒)
* 最大応答待機時間: ヘルスチェックタイムアウト(秒)
* 最大リトライ回数: 異常判定までのリトライ回数
* HTTPパス(URL) / 期待するHTTPレスポンスコード: HTTPプロトコル使用時のみ表示

<a id='change-dsr-health-monitor'></a>
### ヘルスチェック設定変更
**ヘルスチェック**タブで**設定変更**ボタンをクリックすると、ヘルスチェック設定を変更できます。

* ヘルスチェックプロトコル: TCP / ICMP / HTTPから選択
* プロトコル別の必須項目を入力します。
  * TCP: ヘルスチェックポート
  * ICMP: 追加項目なし
  * HTTP: ヘルスチェックポート、HTTPパス、期待するHTTPレスポンスコード
* 遅延時間、最大応答待機時間、最大リトライ回数を設定します。

設定完了後、**確認**ボタンをクリックすると変更事項が適用されます。

!!! danger "注意"
    遅延時間は、タイムアウトより大きいかそれと等しくなければなりません。タイムアウトが遅延時間より大きいと、ヘルスチェックが正常に動作しない場合があります。

!!! tip "ポイント"
    ヘルスチェック要求は、ロードバランサー(DSR)と同一のサブネットに自動割り当てされたヘルスチェック専用IPから送信されます。メンバーインスタンスのSecurity Groupで該当トラフィックを許可する必要があり、ヘルスチェックが正常動作します。詳細については、[ロードバランサー(DSR)概要](/Network/Load%20Balancer(DSR)/ja/overview/)のSecurity Groups設定セクションを参照してください。

<a id='dsr-quota'></a>
## クォータおよび制限事項

ロードバランサー(DSR)使用時に次のクォータおよび制限が適用されます。

| 項目 | 基本制限 | 説明 |
|--|--|--|
| プロジェクトあたりのロードバランサー(DSR)数 | 10個 | プロジェクトあたりで作成可能なロードバランサー(DSR)個数 |
| ロードバランサー(DSR)あたりのメンバー数 | 30個 | 1つのロードバランサー(DSR)に登録可能なメンバー個数 |

!!! tip "ポイント"
    基本クォータを超過して使用する必要がある場合は、カスタマーサポートにお問い合わせください。
